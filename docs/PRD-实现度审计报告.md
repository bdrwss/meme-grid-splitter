# PRD 实现度审计报告

> 审计对象：《小程序"我的"页面：登录鉴权与学员库管理功能需求说明 (PRD - 完整终版)》

## 一、总体结论

**审计时点的实现度约为 0%**：PRD 描述的是一套"云函数 + 云数据库"的多用户云端体系，而小程序当时是刻意定稿的**「零成本纯客户端 + 离线激活码」**架构（见 `.workbuddy/memory/2026-10-26.md`：用户追加零成本硬约束 → 云托管方案作废 → 定稿纯客户端）。两者互斥，因此 PRD 的核心能力（OpenID 静默登录、云端学员总表、远程封禁、管理员后台）此前均未实现，仅有两处**交互形式**相似、**语义完全不同**：

| PRD 要求 | 审计时现状 | 结论 |
| --- | --- | --- |
| 连点 5 次头像 + 口令 666 唤出管理员后台（云函数比对） | 存在"连点 5 次账户卡"彩蛋，但解锁的是**教师模式**（月度 HMAC 教师码，密钥明文在前端包内，恰是 PRD 要避免的形态） | ◐ 形似 |
| 教师批量处理 UID | 教师页有 textarea 粘贴 UID（按行拆分，≤50 个），但用途是**离线生成学员激活码**，无批次、不入库、无 `wx.chooseMessageFile` | ◐ 形似 |

### 与 PRD 的实现差异（需知悉）

1. **解绑微信的主键问题**：`users` 表以 `wx_openid` 为主键，PRD 未定义"清空 OpenID"后的主键冲突。实现为：教师解绑 = 删除其 users 记录 + 将其授权码重置为"未使用"，教师用原授权码在新微信重新注册即完成换绑；学员解绑 = 清空 `bound_openid` + 删除其 users 记录。
2. **Excel(xlsx) 文件解析**需第三方库，首版支持 **CSV/TXT 文件 + 文本粘贴**，xlsx 请另存为 CSV 后导入。
3. **封禁教师时"作废其授权码"**：其已消耗的码本就是"已使用"状态，实现为防御性作废该教师名下仍未使用的码。
4. **管理员口令**：默认 `666` 存于云函数侧（`config` 集合 `admin` 文档可改），前端包内无明文，符合 PRD 安全要求。
5. **管理员入口在封禁全屏拦截页不可触发**（封禁页无头像区）；管理员即开发者本人，正常不会被封禁。
