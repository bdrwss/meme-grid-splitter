# 小程序“我的”页面：登录鉴权与学员库管理功能需求说明 (PRD - 完整终版)

## 一、 核心设计原则与架构说明
1. **底层静默鉴权**：采用 `wx.login` 静默获取用户唯一标识 `OpenID`，无需微信弹窗授权，实现“首次验证绑定，后续无感自动登录”。
2. **单表多视图架构（替代物理双库）**：全网仅维护一张核心**《学员总表》**。通过权限与字段过滤，向管理员展示“一级总库（全量数据）”，向教师展示“二级学员库（仅自己名下的数据）”，确保数据实时同步、零冲突。
3. **隐藏式管理员入口（彩蛋触发）**：不单独开发外部网页工具，在小程序“我的”页面采用**“连续点击 5 次头像 + 输入暗号 `666`”**的方式唤起超级管理员后台，兼顾便捷性与界面整洁度。
4. **封号与删除分离**：区分“禁用拉黑（保留记录但拦截使用）”与“物理删除（清理错录数据）”，防止被删用户重新注册混入，以及防止误删教师导致名下学员变成无主数据。

---

## 二、 数据库表结构设计

### 1. 用户与教师表 (`users`)
用于存储已注册的学员、教师及基础用户信息。
* `wx_openid` (String, 主键)：微信底层唯一标识
* `role` (String)：角色枚举 (`student` 学员 / `teacher` 教师 / `admin` 管理员)
* `xibo_uid` (String, 唯一索引)：绑定的喜播教育 UID
* `auth_code` (String, 选填)：教师注册时消耗的授权码
* `user_status` (Number)：账号状态（`1` 正常 / `2` 已封禁禁用，默认 `1`）
* `create_time` (Date)：绑定时间

### 2. 学员库总表 (`student_pool`)
核心验证库，兼具“一级总库”与“二级教师库”职能。
* `student_uid` (String, 主键)：学员的喜播教育 UID（全网唯一）
* `teacher_uid` (String, 索引)：归属教师的 UID（用于划分教师的二级库）
* `batch_no` (String)：批次名称/期数（如：`202607期`）
* `bound_openid` (String, 默认为空)：已绑定的学员微信 `OpenID`
* `status` (Number)：状态（`0` 未绑定微信 / `1` 已绑定微信 / `2` 已封禁拉黑）
* `update_time` (Date)：最后操作时间

### 3. 教师授权码表 (`auth_codes`)
* `code` (String, 主键)：生成的随机授权码（8 位字母数字组合）
* `status` (Number)：状态（`0` 未使用 / `1` 已使用 / `2` 已作废）
* `used_by_uid` (String, 默认为空)：使用该码的教师 UID
* `used_by_openid` (String, 默认为空)：使用该码的教师微信 `OpenID`
* `create_time` (Date)：生成时间

## 三、 登录与身份绑定流程

### 1. 状态自检与黑名单拦截（每次进入小程序或“我的”页面触发）
1. 小程序调用 `wx.login` 静默获取当前微信的 `OpenID`。
2. 后端查询 `users` 表及 `student_pool` 表：
   * **情况 A（处于封禁状态）**：若 `user_status == 2` 或学员表 `status == 2`，前端直接全屏拦截并提示：“您的账号已被管理员停用，无法使用本工具”。
   * **情况 B（正常已绑定用户）**：直接返回对应角色（`student` 学员 / `teacher` 教师），前端直接渲染对应身份的“我的”页面，**无需再次点击登录或输入 UID**。
   * **情况 C（未注册新用户）**：页面显示默认头像及【点击登录/绑定身份】按钮。

### 2. 首次登录与身份选择
新用户点击登录后，弹出身份选择面板：**【我是学员】** 或 **【我是教师】**。

#### 分支 A：选择“我是学员”
1. **输入信息**：界面要求输入个人的“喜播教育 UID”。
2. **后端核验逻辑**：
   * 在 `student_pool` 表中查询该 `student_uid`：
     * **不存在**：提示“未查询到您的学员 UID，请联系带班老师录入”。
     * **已存在，但 `status == 2（已封禁）`**：提示“该 UID 已被管理员禁用”。
     * **已存在，且 `bound_openid` 不为空**：提示“该 UID 已被其他微信绑定，如需换绑请联系带班老师解绑”。
     * **已存在，且 `bound_openid` 为空 (`status == 0`)**：验证通过！将该微信的 `OpenID` 写入 `bound_openid`，状态改为 `1（已绑定）`，同时在 `users` 表创建一条 `student` 角色记录。
3. **完成登录**：刷新“我的”页面，展示学员专属视图。

#### 分支 B：选择“我是教师”
1. **输入信息**：界面要求同时输入“教师喜播 UID” + “教师授权码”。
2. **后端核验逻辑**：
   * 检查该教师 UID 是否已被其他微信绑定。
   * 在 `auth_codes` 表中查询输入的授权码是否存在且 `status == 0（未使用）`。
   * **验证失败**：提示“授权码无效或已被使用”。
   * **验证通过**：
     1. 将 `auth_codes` 表中该授权码状态改为 `1（已使用）`，写入当前教师的 `UID` 和 `OpenID`（实现一码一微信死绑）。
     2. 在 `users` 表中创建一条 `teacher` 角色记录，绑定该微信 `OpenID` 与教师 `UID`。
3. **完成登录**：刷新“我的”页面，展示教师专属视图及【我的学员库】入口。

## 四、 核心功能模块：“我的”页面权限视图

### 1. 学员视图
* 仅展示个人基础信息（头像区域、已绑定的喜播 UID、所属批次、归属教师）及小程序基础功能，无任何管理入口。

### 2. 教师视图（二级学员库管理）
教师在“我的”页面点击**【我的学员库】**进入管理界面（后端查询强制限定 `teacher_uid == 当前教师UID`）：

* **功能 1：分批次批量上传 UID**
  * **交互方式**：填写“批次名称”（如：`202607期`），提供多行大文本框，支持教师从 Excel 或微信直接复制一整列 UID 粘贴导入（按换行符/逗号自动拆解去重）；同时支持调用 `wx.chooseMessageFile` 选择微信聊天中的 CSV/Excel 文件导入。
  * **冲突处理**：若上传的 UID 在总表中已存在，仅跳过重复项或更新批次号，不报错中断。
* **功能 2：学员列表查询与筛选**
  * 支持按“批次号”筛选、按“UID”搜索、按“状态（未绑定/已绑定/已封禁）”筛选。
* **功能 3：解绑微信（换绑运维）**
  * 点击学员右侧的**【解绑微信】**，清空该 UID 的 `bound_openid` 并将状态重置为 `0（未绑定）`，允许学员用新微信号重新绑定。
* **功能 4：移除学员（受限删除）**
  * **未绑定状态 (`status == 0`)**：教师发现录错 UID，点击【删除】直接从数据库物理抹除。
  * **已绑定状态 (`status == 1`)**：点击【移除】仅将该学员的 `teacher_uid` 清空（解除师生归属关系），不直接物理抹除账号，防止学员端崩溃。

## 五、 开发者/管理员后台（隐藏彩蛋入口 + 最高生杀大权）

### 1. 触发与进入方式（连点 5 次头像 + 口令 `666`）
1. **连点检测**：在“我的”页面中，无论当前是否登录，只要用户在 **2 秒内连续点击顶部【头像区域】满 5 次**，立即触发隐藏逻辑，弹出一个模态输入框（标题：“管理员验证”，带密码掩码输入框）。
2. **口令核验**：
   * 用户在弹窗中输入约定口令：**`666`** 并点击确定。
   * **安全要求**：前端将输入的口令发送至后端云函数进行比对（不在前端本地代码明文写死判断逻辑，防反编译泄露）。
   * **验证结果**：口令错误则提示“指令无效”并关闭弹窗；口令正确（等于 `666`），直接跳转进入**【超级管理员后台】**独立页面。

### 2. 模块 A：教师授权码生成器（内置工具）
* **生成授权码**：点击【生成新授权码】，后端自动生成 8 位随机码存入 `auth_codes` 表（状态为 `0 未使用`），前端支持【一键复制】，管理员可直接粘贴发给教师。
* **授权码列表与状态追踪**：展示所有授权码列表（支持筛选“未使用 / 已使用 / 已作废”），已使用的授权码明确显示绑定的`教师UID`及使用时间。
* **手动单码作废**：针对发错人但尚未被激活的授权码（`status == 0`），管理员可点击右侧【作废】按钮，将其状态直接改为 `2（已作废）`，防止被无关人员拿去注册。

### 3. 模块 B：全网用户管控与一级总学员库（随时封杀/删除任意用户）

#### （1）针对【教师】的管控操作
管理员可查看所有已注册教师列表及其名下学员数量，提供以下操作按钮：
* **【禁用/封杀教师】（不让他使用）**：将该教师的 `user_status` 设为 `2（已封禁）`，同时作废其授权码。该教师打开小程序将直接被拦截无法使用；但**其名下已上传的学员数据完好保留在总库中**，不会丢失。支持随时点击【解封】恢复。
* **【一键划转名下学员】**：当教师离职或调岗时，管理员可点击该教师右侧的【划转学员】，输入接替的新教师 UID，系统自动将该教师名下所有学员的 `teacher_uid` 批量变更为新教师。
* **【解绑教师微信】**：清空该教师 UID 绑定的微信 `OpenID`，允许其更换微信号重新登录。
* **【彻底删除教师】**：二次弹窗确认后，从 `users` 表物理删除该教师记录，并将其名下所有学员的 `teacher_uid` 置空（转为公共无主学员）。

#### （2）针对【学员（一级总库）】的管控操作
管理员无视 `teacher_uid` 限制，可查看、搜索全网所有学员 UID、所属批次与归属教师，并提供以下最高权限操作：
* **【公共批量录入】**：管理员可直接向一级总库批量导入学员 UID（可指定归属教师，也可留空作为公共学员供全网验证）。
* **【修改归属教师】**：管理员可单独点选任意一名或多名学员，手动修改其绑定的 `teacher_uid`（支持跨老师调班）。
* **【禁用/拉黑学员】（不让他使用）**：点击后将该学员 `status` 设为 `2（已封禁）`（同时锁定其已绑定的微信 `OpenID`）。
  * *效果*：该学员再次打开小程序会立刻被黑名单拦截，完全无法使用工具；且即使带班老师后续重新批量导入名单，该 UID 依然保持封禁状态，彻底堵死其使用途径。支持随时点击【解封】恢复。
* **【强制解绑微信】**：清空任意学员的 `bound_openid`，重置为未绑定状态。
* **【彻底删除 UID】**：二次弹窗确认后，将该条 UID 记录从 `student_pool` 和 `users` 表中**物理抹除**（适用于清理录入错误的废数据）。
